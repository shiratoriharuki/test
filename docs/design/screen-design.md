**画面項目の詳細**:

##### SCR001-6: 日付セル

各日付セルは以下の状態を持つ:
- **当月の日付**: 通常表示、クリック可能
- **前月/翌月の日付**: グレーアウト表示（オプション）
- **本日**: ハイライト表示（例: 太枠または特別な背景色）
- **選択中の日付**: 強調表示（例: 青色背景）
- **土日**: 直感的な色分けで背景・文字色を変更（例: 日曜は`#fdecea` + `#c62828`、土曜は `#e8f1ff` + `#1565c0`）。本日/選択状態より優先度は低く、それらに該当する場合は本日/選択のスタイルを適用する。

日付セルの操作:
- **クリック時の動作** (REQ-UC002):
  1. クリックされた日付を選択状態にする
  2. 以前に選択されていた日付のハイライトを解除する
  3. 新しく選択された日付をハイライト表示する
  4. 選択日付に応じた操作オプション（「勤務時間入力」「休暇登録」ボタン等）を表示する
- **ホバー時の動作**: 日付セルの背景色を変更し、クリック可能であることを示す
- **日付選択の保持**: 選択された日付はReactのステート（`selectedDate`）に保存される

日付セルをクリックすると:
- 日付選択とハイライト表示のみを実行する（UC002）
- 選択後に表示される操作ボタンから、勤務時間入力フォーム（SCR-002）または休暇登録フォーム（SCR-003）をメイン画面上のモーダルとして開く（UC003, UC004）

##### SCR001-3: 前月ボタン

**操作** (REQ-UC002):
1. クリック時、表示中のカレンダーを前月に切り替える
2. 年月表示を更新する（例: 「2024年 12月」→「2024年 11月」）
3. 年をまたぐ場合も適切に処理する（例: 「2025年 1月」→「2024年 12月」）
4. カレンダーグリッドを前月の日付で再レンダリングする

**状態管理**: Reactのステート（`currentMonth`）を更新

##### SCR001-4: 次月ボタン

**操作** (REQ-UC002):
1. クリック時、表示中のカレンダーを次月に切り替える
2. 年月表示を更新する（例: 「2024年 11月」→「2024年 12月」）
3. 年をまたぐ場合も適切に処理する（例: 「2024年 12月」→「2025年 1月」）
4. カレンダーグリッドを次月の日付で再レンダリングする

**状態管理**: Reactのステート（`currentMonth`）を更新

##### SCR001-2: 年月表示

**表示形式**: 「YYYY年 MM月」（例: 「2024年 11月」）

**更新タイミング** (REQ-UC002):
- 前月ボタンまたは次月ボタンをクリックした際に自動更新される
- 表示月の変更に連動して即座に反映される

**状態管理**: Reactのステート（`currentMonth`）から生成

**呼び出すAPI**:

| 操作                       | メソッド | エンドポイント                 | 説明                                                     | 関連要件  |
| -------------------------- | -------- | ------------------------------ | -------------------------------------------------------- | --------- |
| カレンダー初期表示         | -        | -                              | APIは使用しない（フロントエンド側で生成）                | UC001     |
| 勤怠データ取得（将来実装） | GET      | `/api/attendance/{employeeId}` | 従業員の勤怠レコード一覧を取得（カレンダーに状態を表示） | UC002以降 |

※ REQ-UC002（カレンダー操作）では、日付選択や月切り替えはフロントエンド側の状態管理のみで実現し、バックエンドAPIは呼び出しません。UC004ではSCR-001からSCR-003を開きますが、レコードの取得・保存・削除APIはSCR-003が呼び出します。

**画面遷移・画面内状態変化**:

| トリガー             | 遷移先画面                      | 条件                                             | 関連要件     |
| -------------------- | ------------------------------- | ------------------------------------------------ | ------------ |

| 日付セル クリック    | 本画面（SCR-001）               | 日付選択状態を更新（遷移なし）                   | UC002        |
| 操作ボタン クリック  | 勤務時間入力フォーム（SCR-002） | 日付選択後、勤務時間入力ダイアログを表示         | UC003        |
| 操作ボタン クリック  | 休暇登録フォーム（SCR-003）     | 日付選択後、休暇登録ダイアログを表示             | UC004        |
| SCR-002 保存成功     | 勤務時間入力フォーム（SCR-002） | SUCCESS02001 を表示し、ダイアログは開いたまま     | UC003        |
| SCR-002 キャンセル   | 本画面（SCR-001）               | 保存せずダイアログを閉じ、選択日付を維持する       | UC003        |
| SCR-003 保存成功     | 本画面（SCR-001）               | ダイアログを閉じ、保存成功メッセージを表示         | UC004        |
| SCR-003 キャンセル   | 本画面（SCR-001）               | 保存せずダイアログを閉じ、選択日付を維持する       | UC004        |

※ SCR-002は既存の詳細仕様に合わせ、保存成功時は成功メッセージを表示してダイアログを維持します。SCR-003は保存成功・キャンセル・削除成功時に閉じ、入力エラーまたはAPIエラー時は入力値を保持して表示を維持します。

**使用メッセージ**:

REQ-UC001（システム起動）およびREQ-UC002（カレンダー操作）では、エラーメッセージやシステムメッセージは使用しません。画面が正常に表示され、操作が正常に動作することを確認します。

**UI/UX要件**:

- **レスポンシブデザイン**: 最新のWebブラウザー（Chrome、Firefox、Safari、Edge）で正常に表示されること
- **パフォーマンス**: ページロード時間は実用的な範囲内であること（具体的な数値目標は今後定義）
- **アクセシビリティ**: 日付セルは視覚的に区別しやすいデザインとすること
- **カレンダー操作**: 直感的に操作できること（月の移動、日付選択）
- **日付選択の視覚的フィードバック** (REQ-UC002):
  - 選択中の日付は明確にハイライト表示される（例: 背景色を青色に変更）
  - 本日の日付は特別なマーキングで表示される（例: 太枠または異なる背景色）
  - ホバー時に日付セルの色が変わり、クリック可能であることを示す
  - 前月/翌月の日付はグレーアウト表示される（オプション）
- **週末の視認性向上**: 一般的なカレンダー配色に合わせ、日曜は柔らかい赤系背景・文字色（`#fdecea`/`#c62828`）、土曜は柔らかい青系背景・文字色（`#e8f1ff`/`#1565c0`）を適用し、操作状態（本日/選択）より優先度を下げる。
- **月切り替え操作** (REQ-UC002):
  - 前月ボタン（<）と次月ボタン（>）は明確に表示され、クリック可能であることが分かりやすいこと
  - ボタンクリック時、カレンダーがスムーズに更新されること（アニメーション不要）
  - 年月表示が正しく更新されること
- **操作オプション表示** (REQ-UC002):
  - 日付選択時、その日付に対する操作オプション（「勤務時間入力」「休暇登録」ボタン等）が適切に表示されること
  - 操作オプションは日付選択状態と連動すること

**備考**:

- 初期表示時は現在月のカレンダーを表示
- 従業員IDは将来の認証機能で取得する予定（現在は固定値 "EMP001" を使用）
- カレンダーコンポーネントは React で実装し、状態管理は React Hooks を使用
- **REQ-UC002 カレンダー操作の技術仕様**:
  - **状態管理**: 以下のReactステートを使用
    - `currentMonth`: 表示中の年月（Date型またはstring型 "YYYY-MM"）
    - `selectedDate`: 選択中の日付（Date型またはstring型 "YYYY-MM-DD"）
  - **カレンダー生成ロジック**: 
    - JavaScriptの`Date`オブジェクトを使用して、指定月の日付配列を生成
    - 月初の曜日、月末の日付を計算し、7列×最大6行のグリッドを構築
  - **イベントハンドラー**:
    - `handleDateClick(date)`: 日付セルクリック時の処理
    - `handlePrevMonth()`: 前月ボタンクリック時の処理
    - `handleNextMonth()`: 次月ボタンクリック時の処理
  - **スタイリング**: CSS Modules または Tailwind CSS を使用し、ハイライト状態のスタイルを適用
  - **パフォーマンス**: `useMemo`フックを使用してカレンダー日付配列の再計算を最適化

#### SCR-002: 勤務時間入力フォーム

**UI種別**: モーダルダイアログ

**表示方式**:
- SCR-001 のオーバーレイ上に表示する
- 独立ルートや別ページ遷移は発生しない
- 保存完了またはキャンセル時にダイアログを閉じ、SCR-001 の選択日付コンテキストへ戻る

**関連要件**: REQ-UC003（勤務時間入力）

**関連シーケンス図**: SEQ-UC003-001〜005（`docs/design/domain/sequence/SEQ-REQ-UC003-勤務時間入力.md`）

**画面概要**:
- SCR-001 で選択した日付の出勤・退勤時刻を入力して保存するダイアログ
- 選択日付に既存の勤怠レコードがある場合は、その時刻を初期表示して更新できる
- 未来日付も入力・保存できる

**表示トリガー**:
- SCR-001 で日付を選択後、「勤務時間入力」ボタン（`data-testid="btn-work-time"`）をクリック（UC003 で有効化する）

**画面項目**:

| 項目ID   | 項目名       | 種別               | 必須 | 形式・制約                                   | 初期値                                   | 備考                                           |
| -------- | ------------ | ------------------ | ---- | -------------------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| SCR002-1 | 対象日付     | 表示テキスト       | -    | 「YYYY年M月D日」                             | SCR-001 の選択日付                       | 編集不可。API には `YYYY-MM-DD` で送信         |
| SCR002-2 | 出勤時刻     | テキスト入力       | ✓    | `HH:MM`（00:00〜23:59、24時間表記）          | 既存レコードの出勤時刻、なければ空       | `data-testid="clock-in-input"`                 |
| SCR002-3 | 退勤時刻     | テキスト入力       | ✓    | `HH:MM`（00:00〜23:59、24時間表記）          | 既存レコードの退勤時刻、なければ空       | `data-testid="clock-out-input"`                |
| SCR002-4 | 保存ボタン   | ボタン             | -    | -                                            | -                                        | `data-testid="btn-save"`。送信中は非活性       |
| SCR002-5 | キャンセル   | ボタン             | -    | -                                            | -                                        | `data-testid="btn-cancel"`。保存せず閉じる     |
| SCR002-6 | エラー表示   | メッセージ領域     | -    | -                                            | 非表示                                   | `data-testid="error-message"`。項目直下に表示  |
| SCR002-7 | 成功表示     | メッセージ領域     | -    | -                                            | 非表示                                   | `data-testid="success-message"`                |

※ 時刻入力は `HH:MM` 文字列で受け付ける（E2E で `25:00` など無効値を入力できるよう、`type="time"` ではなくテキスト入力とする）。

**バリデーション**（保存ボタンクリック時にフロントエンドで実施。バックエンドでも同一ルールで再検証）:

| 順序 | 対象           | ルール                                       | エラーメッセージ |
| ---- | -------------- | -------------------------------------------- | ---------------- |
| 1    | 出勤・退勤時刻 | 正規表現 `^([01][0-9]\|2[0-3]):[0-5][0-9]$` に一致 | ERR03002         |
| 2    | 出勤・退勤時刻 | 未入力でない（形式エラーがある場合は 1 を優先） | ERR03003         |
| 3    | 出勤 / 退勤    | 出勤時刻 < 退勤時刻（同時刻は不可）          | ERR03001         |

- 検証エラー時は API を呼び出さず、フォームを閉じず、入力値を保持する
- 日付に関する検証は行わない（未来日付を許容）

**呼び出すAPI**:

| 操作                   | メソッド | エンドポイント                         | 説明                                                            | 関連要件 |
| ---------------------- | -------- | -------------------------------------- | --------------------------------------------------------------- | -------- |
| ダイアログ表示時       | GET      | `/api/attendance/{employeeId}/{date}`  | 既存レコードを取得して初期表示。404 の場合は空フォームを表示    | UC003    |
| 保存ボタン クリック    | POST     | `/api/attendance`                      | 勤務時間を保存（既存なら更新）。`status` は `WORK` 固定         | UC003    |

**画面遷移・画面内状態変化**:

| トリガー                 | 遷移先                 | 条件                                               | 関連要件 |
| ------------------------ | ---------------------- | -------------------------------------------------- | -------- |
| 勤務時間入力ボタン       | 本画面（SCR-002）      | 日付選択済み。ダイアログを表示                     | UC003    |
| 保存成功                 | 本画面（SCR-002）      | SUCCESS02001 を表示。ダイアログは開いたまま        | UC003    |
| 閉じる操作（キャンセル） | SCR-001                | 保存せずダイアログを閉じ、選択日付を維持する       | UC003    |
| バリデーションエラー     | 本画面（SCR-002）      | エラーを表示し、ダイアログは開いたまま             | UC003    |

※ 保存成功後はメッセージを表示してダイアログを開いたままにする（E2E で成功メッセージを確認できるようにするため）。閉じる操作はキャンセルボタンで行う。

**使用メッセージ**:

| メッセージID | 表示条件                                         | 表示位置   |
| ------------ | ------------------------------------------------ | ---------- |
| SUCCESS02001 | 保存成功（新規・更新とも）                       | SCR002-7   |
| ERR03001     | 出勤時刻 >= 退勤時刻                             | SCR002-6   |
| ERR03002     | 時刻が `HH:MM` 形式でない                        | SCR002-6   |
| ERR03003     | 出勤または退勤時刻が未入力                       | SCR002-6   |
| ERR99001     | サーバーエラー（5xx）                            | SCR002-6   |
| ERR99002     | ネットワークエラー                               | SCR002-6   |

**UI/UX要件**:
- エラーは分かりやすい日本語で、問題の項目の近くに表示する
- 新たな保存操作・入力変更時は前回の成功/エラー表示をクリアする
- 保存中は保存ボタンを非活性にして二重送信を防ぐ

**備考**:
- 従業員IDは認証機能実装までは `EMP001` 固定
- `SCR-001` の「勤務時間入力」ボタンの `disabled` を解除し、SCR-002 を開くハンドラーを追加する

#### SCR-003: 休暇登録フォーム

**UI種別**: モーダルダイアログ

**表示方式**:
- SCR-001 のオーバーレイ上に表示する
- 独立ルートや別ページ遷移は発生しない
- 保存成功、キャンセル、削除成功時にダイアログを閉じ、SCR-001 の選択日付コンテキストへ戻る
- 入力エラー、取得エラー、保存・削除APIエラー時はダイアログを開いたままにし、入力値を保持する

**関連要件**: REQ-UC004（休暇登録）

**関連シーケンス図**: SEQ-UC004-001〜004（`docs/design/domain/sequence/SEQ-REQ-UC004-休暇登録.md`）

**画面概要**:
- SCR-001 で選択した日付に対する休暇種別と任意のメモを登録・更新・削除するダイアログ
- 表示時に選択日の勤怠レコードを取得し、休暇レコードがあれば登録済みの値を初期表示する
- 未来日付を含む任意の日付を対象とする
- 対応する休暇種別は Sick Leave、Personal Leave、Business Trip

**表示トリガー**:
- SCR-001 で日付を選択後、「休暇登録」ボタンをクリックする
- 選択日付がない場合は起動できない

**画面項目**:

| 項目ID   | 項目名             | 種別           | 必須 | 形式・制約 | 初期値 | 備考 |
| -------- | ------------------ | -------------- | ---- | ---------- | ------ | ---- |
| SCR003-1 | 対象日付           | 表示テキスト   | -    | `YYYY年M月D日` | SCR-001 の選択日付 | 編集不可。APIには `YYYY-MM-DD` で送信 |
| SCR003-2 | 休暇種別           | 選択入力       | ✓    | Sick Leave / Personal Leave / Business Trip | 既存休暇レコードの種別。新規時は未選択 | API/DBのコード値は下記「設計上の注意」を参照 |
| SCR003-3 | メモ               | テキストエリア | -    | 任意入力 | 既存レコードのメモ。新規時は空 | 空欄は `null` として送信する設計案 |
| SCR003-4 | 保存ボタン         | ボタン         | -    | - | - | 送信中は非活性にし、二重送信を防止 |
| SCR003-5 | キャンセルボタン   | ボタン         | -    | - | - | 保存せずダイアログを閉じ、SCR-001へ戻る |
| SCR003-6 | 削除ボタン         | ボタン         | -    | - | 既存休暇レコードがある場合のみ表示 | クリック時に削除確認を表示 |
| SCR003-7 | エラー表示         | メッセージ領域 | -    | - | 非表示 | 入力エラー・取得・保存・削除APIエラーを表示 |

**初期表示・状態制御**:

1. ダイアログ表示時に `GET /api/attendance/{employeeId}/{date}` を呼び出す
2. 200 の場合、status が休暇を表すレコードであれば休暇種別とメモを初期表示し、削除ボタンを表示する
3. 404 の場合は未登録として空フォームを表示し、削除ボタンを表示しない
4. 取得中はフォーム操作を抑止し、取得エラー時はエラーを表示する。通信・サーバーエラーを未登録として扱わない
5. 同じ日付の既存レコードが `WORK` の場合、休暇フォームから暗黙に上書きしない。勤務レコードを休暇で置換する業務ルールとAPI動作が決まるまで保存・削除操作を無効にし、対象レコードが勤務であることを表示する

**バリデーション**:

| 順序 | 対象 | ルール | エラー時の動作 |
| ---- | ---- | ------ | -------------- |
| 1 | 休暇種別 | Sick Leave、Personal Leave、Business Trip のいずれかを選択する | APIを呼び出さず、SCR003-7に入力エラーを表示 |
| 2 | メモ | 任意入力。入力上限はAPI・DB仕様に合わせて定義する | APIの上限超過時は400エラーを表示し、値を保持 |
| 3 | 対象日付 | 過去・未来を含む任意の日付を許容する | 日付範囲による拒否は行わない |

- フロントエンドで入力検証を行い、バックエンドでも同じ業務ルールを検証する
- エラー時はAPI成功扱いにせず、フォームを閉じない

**呼び出すAPI**:

| 操作 | メソッド | エンドポイント | リクエスト・応答と画面動作 | 状態 |
| ---- | -------- | -------------- | -------------------------- | ---- |
| ダイアログ表示時のレコード取得 | GET | `/api/attendance/{employeeId}/{date}` | 200の場合は休暇種別・メモを表示。404の場合は空フォームを表示 | 実装済み |
| 保存ボタン押下 | POST | `/api/attendance` | `employeeId`、`attendanceDate`、休暇status、`clockInTime: null`、`clockOutTime: null`、`notes`を送信。200の場合は閉じてSCR-001へ戻る | エンドポイント実装済み。UC004種別の対応とWORKレコード上書き制御は要整合 |
| 削除確認後 | DELETE | `/api/attendance/{employeeId}/{date}` | 対象レコードを削除する設計案。成功時は閉じてSCR-001へ戻る | 未実装。OpenAPI・バックエンドへの追加が必要 |

**休暇種別とAPI/DBコードの設計案**:

| 画面表示値 | status候補 |
| ---------- | ---------- |
| Sick Leave | `SICK_LEAVE` |
| Personal Leave | `PERSONAL_LEAVE` |
| Business Trip | `BUSINESS_TRIP` |

※ status候補は現行OpenAPI・DB制約のenumに揃っていません。コード値を確定し、OpenAPI、DBのCHECK制約、バックエンド検証、画面の送受信値を同時に更新する必要があります。現行の `PAID_LEAVE` / `UNPAID_LEAVE` との対応は要件から決定できないため、本設計では自動対応させません。

**画面遷移・画面内状態変化**:

| トリガー | 遷移先 | 条件 |
| -------- | ------ | ---- |
| SCR-001の「休暇登録」ボタン | 本画面（SCR-003） | 日付選択済み。モーダルを表示し、GETで既存レコードを取得 |
| 取得成功（200） | 本画面（SCR-003） | 休暇種別・メモを初期表示 |
| 未登録（404） | 本画面（SCR-003） | 空フォームを表示 |
| 保存成功（200） | SCR-001 | ダイアログを閉じ、保存成功メッセージを表示 |
| キャンセル | SCR-001 | 保存せず閉じる。選択日付を維持 |
| 削除ボタン | 本画面（SCR-003） | 削除確認ダイアログを表示 |
| 削除確認のキャンセル | 本画面（SCR-003） | 削除APIを呼び出さず、フォームを維持 |
| 削除成功 | SCR-001 | ダイアログを閉じ、削除成功メッセージを表示 |
| 入力・APIエラー | 本画面（SCR-003） | エラーを表示し、入力値を保持 |

**使用メッセージ**:

| メッセージ | 表示条件 | 表示位置 |
| ---------- | -------- | -------- |
| SUCCESS02002 | POST が 200 で成功 | SCR-001 |
| SUCCESS02003 | DELETE が成功（追加設計） | SCR-001 |
| ERR02001 | 休暇保存時に同日 WORK レコードが存在（409） | SCR003-7 |
| ERR02002 | 削除対象が休暇以外のレコード（409） | SCR003-7 |
| ERR02003 | 削除対象の休暇レコードが未検出（404） | SCR003-7 |
| ERR03004 | 休暇種別が未選択 | SCR003-7 |
| ERR03005 | APIが未定義の休暇種別を返した（400） | SCR003-7 |
| ERR03006 | 休暇登録リクエストに出退勤時刻を指定（400） | SCR003-7 |
| ERR99001 | サーバーエラー（5xx） | SCR003-7 |
| ERR99002 | ネットワークエラー | SCR003-7 |

※ SUCCESS02003、ERR02002、ERR02003のDELETE応答はOpenAPI追加設計であり、バックエンド実装が必要です。404のGETは未登録状態として扱い、エラーメッセージを表示しません。

**UI/UX要件**:
- 休暇種別は選択肢を明示し、選択状態を認識できるようにする
- 削除は確認ダイアログで明示的に確定した場合のみ実行する
- 保存・削除処理中は該当ボタンを非活性にして二重送信を防ぐ
- 入力変更または再操作時に前回のエラー表示をクリアする
- エラー時は日本語で原因を示し、入力値を保持する

**備考**:
- 従業員IDは認証機能実装までは `EMP001` 固定
- 休暇用DELETE APIは現行設計・実装に存在しないため、実装前にOpenAPIとバックエンド設計を更新する
- 既存 `WORK` レコードを休暇で置き換える可否は業務ルールとして未決定。決定までは既存の勤務情報を上書きしない
